# Design System: MarkDN

## Overview

**Creative North Star: "The Midnight Line"**

MarkDN is drawn as a transit diagram fired in midnight-blue enamel. A document is a line. Every top-level folder is a line in its own ink, its documents are the stations on it, and the open document's headings are a line of their own, with the section in view lit as an interchange ring. The person reading always knows where they are: which line, which station, and how far along it.

The world has two materials and keeps them apart. The **enamel shell** (rail, top bar, tab bar, every edge) is the same in light and dark: midnight ground, porcelain type, signage in uppercase condensed letters. The **document card** sits inset in the enamel with a generous 14px corner: porcelain in light, deep enamel in dark. The card is where reading and writing happen, and it stays quiet: system type, hairline boxes, and colour only where the document's own syntax or state asks for it. The four line inks (scarlet, cobalt, amber, green) belong to lines, station rings and state. They are never decoration.

It is sized for glass first. Every control in the shell is a 44px target, tightened to 34px only under a fine pointer, and the layout moves through three arrangements (iPhone tab bar, iPad slide-over rail, wide split view) without changing what anything means. It refuses the category default of a grey list sidebar beside a grey page, and it refuses glass, glow and gradient: depth here is enamel against porcelain and nothing else.

**Key Characteristics:**
- A document is a line; folders are lines; headings are stations; the open document is an interchange ring.
- Midnight enamel shell, identical in both appearances; porcelain document card (deep enamel in dark), inset 12px with a 14px corner.
- Four line inks used only as track, station rings and state. Scarlet is the root "Main line" alone among lines.
- Signage in uppercase Barlow Condensed; prose and UI body in the system face; source and code in ui-monospace.
- 44px touch targets everywhere in the shell, 34px under a fine pointer.
- Flat: no drop shadows, no gradients, hairline edges and tonal contrast only.
- Motion is state only (120ms and 180ms on ease-out-quart) and disappears under reduced motion.

## Colors

A deep midnight enamel shell carrying four saturated transit inks, around a porcelain document whose own palette is low-chroma and redefined for dark.

### Primary
- **Midnight Enamel** (oklch(0.205 0.068 271)): the shell. Rail, top bar, tab bar, phone panels and the frame around the card. The same in both appearances, so the shell reads as one object whatever the system theme.
- **Raised Enamel** (oklch(0.26 0.066 270)): the hover and pressed ground on enamel, and the ground of the notice banner. The only step up the shell takes.
- **Enamel Hairline** (oklch(0.39 0.052 270)): outlines of shell controls (segmented control, rail icons, search field, banner) and the rule under the rail's document line.
- **Porcelain Type** (oklch(0.965 0.004 95)) and **Muted Porcelain** (oklch(0.80 0.025 268)): text on enamel. Porcelain for what is current or selected; muted for everything at rest. Porcelain is also the fill of every station at rest and the plate of the selected segment.

### Secondary: the line inks
- **Main Line Scarlet** (oklch(0.585 0.215 27)): the root "Main line", which the documents at the top of the root ride. Outside the line network it is state only: the Save plate when there are edits, the unsaved dot beside the station name, and the rule under the active tab bar label.
- **Cobalt** (oklch(0.585 0.205 262)), **Amber** (oklch(0.84 0.165 85)) and **Green** (oklch(0.655 0.165 145)): the branch inks. Each top-level folder is assigned one by a hash of its name, so a folder keeps its colour when another is added beside it. Amber and green are light inks and carry enamel type on a chip; scarlet and cobalt carry porcelain type (oklch(0.985 0.003 95)).
- Amber has a second job: an agent's change. A station an agent touched gets an amber ring and an amber service-alert triangle, and the notice banner's dot is amber.

### Tertiary: state on the card
- **Signal** (oklch(0.54 0.205 27); dark oklch(0.66 0.2 27)): scarlet tuned for the card. Text selection, the search hit, the active palette row, link underlines, the active MDX tab rule, errors. Its tints (12% and 6% light, 18% and 9% dark) are the washes for selection, hover in menus and pickers, and error headers.
- **Cobalt Focus** (oklch(0.53 0.21 262); dark oklch(0.72 0.16 262)): every focus ring, 2px at 2px offset, and the 2px inset bar on focused menu and picker rows.
- **Caution** (oklch(0.5 0.11 70); dark oklch(0.85 0.15 85)): text-weight amber for the warning alert header on porcelain, over an amber tint.

### Neutral: the document card
- **Porcelain Surface** (oklch(0.968 0.004 95); dark oklch(0.235 0.052 270)): the card itself, the panes, the overlays.
- **Card Panel** (oklch(0.925 0.008 265); dark oklch(0.265 0.055 270)): code blocks, mermaid diagrams, inline code, table headers, MDX header strips, overlay footers.
- **Hairline** (oklch(0.875 0.01 265); dark oklch(0.33 0.048 270)) and **Strong Hairline** (oklch(0.775 0.014 265); dark oklch(0.42 0.045 270)): separating rules and component edges on the card. Decorative, deliberately below 3:1.
- **Control Edge** (oklch(0.565 0.025 265); dark oklch(0.6 0.04 268)): the border that identifies an interactive control on the card, kept at 3:1 for WCAG 1.4.11.
- **Ink** (oklch(0.235 0.04 268); dark oklch(0.945 0.006 95)), **Muted Ink** (oklch(0.455 0.03 268); dark oklch(0.79 0.022 268)), **Faint Ink** (oklch(0.48 0.025 268); dark oklch(0.75 0.022 268)): body, secondary and metadata text on the card.
- **Syntax** (`syn-marker`, `syn-heading`, `syn-code`, `syn-link`, `syn-url`, `syn-html`): low-chroma source highlighting, so a highlighted document still reads as a document. Rendered code blocks map Shiki's css-variables theme onto the same six tokens, with comments and punctuation in Muted Ink.

### Named Rules
**The Ink Is Track Rule.** The line inks are lines, station rings and state, never decoration. No ink fills a panel, colours body text, or appears on a control that is not carrying state.

**The Main Line Rule.** Among lines, scarlet belongs to the root "Main line" alone; top-level folders hash into cobalt, amber or green, so no folder can be mistaken for the main line.

**The Two Palettes Rule.** The enamel tokens paint the shell and never change with the theme. The document tokens paint the card and everything that floats over it, and each has a designed dark value. Mermaid diagrams take their colours from the document tokens (surface, panel, ink, muted ink, control edge, and the UI face), resolved at render time so they follow the theme; never from the line inks.

**The Cobalt Is Focus Rule.** Keyboard focus is always cobalt. Scarlet means "act" or "unsaved", never "focused".

## Typography

**Signage Font:** Barlow Condensed, 500 and 600, bundled (with DIN Condensed, Arial Narrow, sans-serif)
**Body Font:** system-ui (with -apple-system, Segoe UI, sans-serif)
**Mono Font:** ui-monospace (with SFMono-Regular, SF Mono, Menlo, monospace)

**Character:** Transit signage over a native reading face. The condensed uppercase letters name places (lines, stations, views, tabs) and read at a glance from across a room; the system face carries everything a person actually reads, so prose feels native on iPad and iPhone.

### Hierarchy
- **Sign Display** (600, 1.5rem, 0.03em, uppercase): the place title on an iPhone panel (Documents, Outline).
- **Sign Title** (600, 1.375rem, 0.02em, uppercase): the wordmark; the iPhone bar's place name uses the same size at 0.04em.
- **Sign Headline** (600, 1.25rem, 0.03em, uppercase): the station name in the top bar and at the head of the rail's document line (1.125rem on iPhone).
- **Sign Label** (600, 0.9375rem, 0.07em, uppercase): segmented control, header buttons, banner dismiss; folder name boards at 0.08em.
- **Sign Chip / Tab** (600, 0.8125rem, 0.09em for line chips at 1.3 line height; 0.08em for tab bar labels; 500 at 0.1em for the saved/edited state): the smallest signage.
- **Document Headings** (system face, 1.25 line height, -0.012em): h1 1.6rem/650, h2 1.25rem/620 with a hairline under it, h3 1.05rem/600, h4 0.95rem/600 in Muted Ink.
- **Body** (400, 1.0625rem, 1.65): rendered prose, capped at 68ch. Tables, code and diagrams may run wider.
- **UI Body** (400, 0.9375rem, 1.5): tree rows, stations, field labels, menus, buttons on the card.
- **Micro Label** (600, 0.75rem, 0.07em, uppercase, system face): header strips inside the card: MDX alert and callout headers, picker title, palette section names.
- **Mono** (400, 0.9375rem, 1.7): the source pane, sized from settings; code blocks at 1.6; key hints and readouts at 0.75rem.

### Named Rules
**The Signage Rule.** Every label in the enamel shell (line, station, view, tab, folder) is uppercase Barlow Condensed, tracked. Nothing a person reads as prose is ever set in it, and the document card never uses it.

**The Glass First Rule.** Sizes are fixed rem steps chosen for touch screens: 17px body, 15px UI, 13px the smallest label, 12px only for micro labels and key hints. Never fluid.

## Layout

The shell is an enamel frame on every edge; the document card is inset in it by 12px on every side but the rail's, and the iPhone notch and home indicator always sit over enamel, never over the document. The top bar is at least 56px tall and reads left to right as a sign: rail toggle, wordmark, the line chip, the station name, its saved or edited state; then the Source / Split / Render segmented control, Settings, and Save.

The rail is 300px of enamel with a 16px gutter. **The document's own line sits first in it**, headed by its line chip and station name and closed off with an enamel hairline, then the search row (a field-shaped button to the palette, plus square Search and New controls), the root label, and the line network of documents.

Three arrangements, by width:
- **Phone (max-width 599px):** a bottom tab bar with four places, Read, Documents, Outline and Search, clearing the home indicator. The card runs edge to edge with square corners under the bar. The bar drops the wordmark text, the state and the rail toggle; Read shows Edit/Done and shows Save only when there are edits; Documents shows New and a Settings gear. Documents and Outline are full-height enamel panels above the tab bar.
- **Compact (600 to 1023px):** iPad portrait and split screen. The rail slides over the card (min(340px, 86vw), its open edge rounded to the card radius) above an enamel scrim at 55% that closes it, so the document keeps its full width.
- **Wide (1024px and up):** the rail sits beside the card and collapses outright from the toggle (⌘B), never by animating its width. Split view needs at least 760px; below that the Split segment is disabled rather than offering a mode that cannot be honoured.

In split view the panes are two equal columns around a 21px sync rail. The line network separates lines by a 12px gap; runs of the same line are drawn unbroken.

### Named Rules
**The Line First Rule.** Where the reader is in the open document is the thing looked for most, so its line comes first in the rail; the network of documents comes second.

**The One Target Rule.** Every control in the shell is at least 44px tall (34px under a fine pointer). Key hints are hidden on glass, where they mean nothing.

## Elevation & Depth

The system is flat. Depth is the contrast between the enamel shell and the inset porcelain card, plus one tonal step (Raised Enamel) for hover and notices in the shell. Overlays (command palette, component picker, settings, context menu) are porcelain plates with a strong hairline edge and no shadow; the picker family sits over a scrim. Where `box-shadow` appears it is a zero-blur spread used as a ring or a rule, never as lift: the 1px ring around a search hit, the 8px spread that extends the active block's ink wash, the 3px tint ring on the new-document field, the 2px inset cobalt bar on a focused menu row, and the 1px inset rule under the active MDX tab.

### Named Rules
**The No-Shadow Rule.** Nothing in MarkDN casts a shadow. Menus, palettes and sheets are separated by their edge and their material, not by blur.

## Shapes

Two radii carry the world: the document card's 14px corner and the 10px corner on every shell control, field, row and banner (7px on the segments inside the segmented control). Line chips are full pills. Content inside the card keeps tight hairline boxes: 3px for code blocks, diagrams, images and MDX components, 2px for inline code, key caps and the source readouts, 4px for overlays.

Station geometry is the diagram's vocabulary and is fixed: a **circle** is a document or a heading; a **square** is a folder, filled with ink when it is a line's name board (17px, 4px corner) and porcelain with an ink border when it is a stop on a line (15px, 3px corner); a **ring** (enamel centre, porcelain border, scaled up) is where you are; a short **tick** across the line is a minor heading. Lines are straight vertical rules; the wordmark is the one drawing where they bend, at 45° and 90° only.

### Named Rules
**The Station Geometry Rule.** Shape says what a stop is, ink says which line it is on. Never swap the two: a folder is never a circle and the current place is never anything but the ring.

## Components

### Buttons
- **Shape:** gently rounded (10px), 44px tall, 16px side padding.
- **On the card:** a hairline outline in Control Edge, transparent ground, Ink text, 600 weight; hover darkens the edge to Ink, press washes it in signal tint. Quiet variant drops the outline until hover.
- **In the top bar:** the same control speaks signage: uppercase condensed, tracked 0.07em, enamel-hairline outline, porcelain text; hover raises it to Raised Enamel with a porcelain edge. A pressed quiet button (Edit) gets a porcelain outline.
- **Save:** the one scarlet plate in the shell, with porcelain text, shown scarlet only when there is something to save (disabled and muted otherwise); hover deepens it to oklch(0.54 0.215 27).
- **Icon controls:** 44px squares with a 20px stroked icon (1.8 stroke, round caps), enamel-hairline outline in the rail and none in the bar; hover and active get a porcelain edge on Raised Enamel.

### Segmented control
- The platform's segmented control in enamel: a 3px-padded enamel-hairline frame at 10px, segments 36px tall and at least 72px wide at 7px.
- The selected segment is a porcelain plate with enamel text, so the view in use reads from across a room. Hover on the others is Raised Enamel. Disabled segments drop to half opacity.

### Line chip and station sign
- A pill in the line's ink with uppercase condensed text (enamel type on amber and green, porcelain on scarlet and cobalt), followed by the station name in Sign Headline. Used in the top bar, at the head of the rail's document line and on the iPhone Outline panel. The edited state is a small uppercase label with an 8px scarlet dot.

### Inputs / Fields
- **Rail search:** a button dressed as a field, because the command palette is the one search surface. Enamel-hairline outline, 10px, 44px, muted text with the ⌘P hint on the right; hover and active turn the edge porcelain over Raised Enamel.
- **Fields on the card** (settings, multibuffer): mono text, Control Edge outline, small radius. Focus is the global cobalt ring.

### The line network (document tree)
- Each row is a 44px target with a 40px left inset; the line is a 5px rule in its ink 15px from the edge, and each document is a 15px porcelain station ringed 3px in the ink.
- A top-level folder is its line's name board: an ink-filled 17px square with the folder name in uppercase condensed porcelain and a chevron that turns 90° when open. A closed folder is a terminus with no track. Documents at the root ride the "Main line" under a scarlet board of their own.
- A nested folder is a small square station on its parent's line, in muted smaller text, and the track runs straight through it. **Every line ends at its true last station however deep it sits** (the row marked `data-terminus`); each line starts at its first station and is followed by a 12px gap.
- The open document is the interchange ring: the station scales to 1.45 with an enamel centre and a porcelain border, and its name goes porcelain and 600. Hover is Raised Enamel. Keyboard focus is a cobalt ring inset on the row; the tree is one Tab stop driven by the arrow keys.

### The document line (outline)
- The open document's headings, evenly spaced as on a diagram: order, not distance, is what a reader navigates by. A 6px rule in the document's ink, starting and ending at the first and last station.
- h1 and h2 are 18px porcelain stations ringed 4px in the ink (h1 labels in porcelain 600); h3 is a 14×4px tick across the line in smaller text. Names clamp to two lines; each station is a 44px target that jumps the document there.
- The section in view is the lit interchange: the marker scales to 1.4 with an enamel centre and a porcelain ring (a tick becomes a full ring). The transition runs 180ms.
- A section an agent changed is a service alert: an amber ring on its station and an amber triangle at the row's end, with "changed by an agent" for assistive technology, until it is visited.

### Sync rail
- The 21px column between the panes in split view, hairlines either side. The document's line runs down it as a 3px rule at 35%; each block is a 2px tick at 80%, and the caret's block is a 13px station ring. It moves by translating a single strip on scroll, so scrolling stays at frame rate. In the rendered pane the caret's block gets a 9% wash of the same ink.

### Tab bar (iPhone)
- Four equal columns on enamel with an enamel-hairline top edge and bottom padding for the home indicator. Each item is 52px tall: a 24px stroked line-diagram icon over an uppercase condensed label. The active item goes porcelain with a 2px scarlet rule under its label. Sections only: Save and Edit live in the top bar with the document they act on.

### Banner and decision bar
- A notice on the line: an enamel strip under the top bar (Raised Enamel, enamel hairline, 10px, 44px) with a 10px amber dot. A decision (unsaved edits about to be replaced, a file changed on disk) uses the same strip rather than a modal, so the document stays readable: the first action is a porcelain plate, the rest quiet, focus lands on the first and Escape takes the last, which always changes nothing.

### Document card and rendered content
- **Card:** Porcelain Surface, 14px corner, inset in the enamel; the preview pads 18px 26px 60px.
- **Links:** Ink text with a 1.5px signal underline at 2px offset; hover turns the text signal.
- **Code blocks, mermaid diagrams, images:** Card Panel ground, 1px hairline, 3px corner. Mermaid renders under strict security with its theme read from the document tokens at each render.
- **MDX components** (Alert, Callout, Card, Tabs): full hairline boxes with a Card Panel header strip in Micro Label, capped at 68ch. Info and success headers stay neutral; warning takes the caution tint and Caution text; error takes the signal tint and Signal text. Each alert carries a drawn 12px glyph so the four differ in shape, not only colour. The active MDX tab is the surface colour with a 1px signal rule beneath.

### Overlays
- **Command palette, component picker, settings:** porcelain plates with a strong hairline and 4px corner, entering with a 4px drop and fade over 180ms. The active row is the signal tint; matched characters are Signal 600; paths are mono, truncated from the left so the tail stays.
- **Context menu:** the app's own, on the same porcelain and edge; hover is the soft signal tint, keyboard focus the inset cobalt bar, destructive items Signal. It enters over 120ms.

### Wordmark
- Four lines (scarlet, cobalt, amber, green) meeting at one porcelain interchange ring on enamel, bending only at 45° and 90°, beside "MARKDN" in Sign Title. Geometry only, so one drawing serves 16px and 1024px.

## Do's and Don'ts

### Do:
- **Do** put every shell surface (rail, top bar, tab bar, phone panels) on Midnight Enamel and every document surface on the card tokens, so the two palettes never mix.
- **Do** draw a folder as a line and a document as a station on it, with the open document as the interchange ring; assign branch inks with `lineFor`, by folder name.
- **Do** run a line's track unbroken to its true last station, through any nested folders, and stop it there.
- **Do** keep the document's own line first in the rail on iPad and desktop, and on its own Outline tab on iPhone.
- **Do** set shell labels in uppercase Barlow Condensed, tracked 0.02em to 0.1em, and keep prose in the system face.
- **Do** give every shell control a 44px target (34px under a fine pointer) and show focus as a 2px cobalt ring.
- **Do** mark an agent's change with amber on the stations it touched, and say it in text for assistive technology.
- **Do** theme anything drawn on the card, mermaid included, from the document tokens so it follows light and dark.
- **Do** honour `prefers-reduced-motion`: every transition and animation collapses, and state still reads statically.

### Don't:
- **Don't** use a line ink as decoration: no ink-filled panels, no ink text on the card, no ink on a control that is not carrying state.
- **Don't** give a folder scarlet; scarlet is the root Main line's among lines, and otherwise only Save, unsaved and the selected tab.
- **Don't** put a coloured or thick stripe on one side of a card, alert, callout, row or menu item to mark its kind or state. The only vertical ink rules are the lines themselves, drawn through their stations; a blockquote keeps its 1px neutral hairline.
- **Don't** put a drop shadow on menus, palettes, sheets or anything else; separate overlays by edge and material.
- **Don't** use gradients, glass, blur or glow on any surface.
- **Don't** set prose, document headings or card labels in the condensed signage face.
- **Don't** animate the rail's width or add load sequences; motion is state feedback only.
- **Don't** let a diagram, code block or MDX component bring its own palette; it speaks the document tokens.
